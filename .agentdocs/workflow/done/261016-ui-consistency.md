# 全局界面视觉统一

## 目标与范围

以软件更新页的视觉层级统一主工作区、设置、连接和安全弹窗、内置编辑器、通知、运维和手机 Shell。保留现有业务交互、终端字号和 ANSI 色、文件 Grid、拖拽约束及手机键盘桥。

## 已确认的现状

- app.css 由 app.rs 内嵌；主题和强调色在 kt-window 上设置，更新独立弹层另行传递。
- 多处按钮和输入重复定义；部分浅色覆盖和硬编码蓝色绕过用户强调色。
- 仅更新分类在 640px 下调整设置导航，其他分类仍可能拥挤。
- 更新页已完成的状态逻辑、发布日志安全解析和焦点脚本不在本次重写范围。

## 实施方案

1. 共用按钮、表单、开关与可见焦点，延续主题变量，选中态使用强调色，悬停使用中性色。
2. 设置采用一致间距和分隔线；弹窗共用标题、表单与操作区；不将工作区改造成卡片布局。
3. 主框架移除装饰渐变与大阴影，连接、文件、监控和运维保留信息密度。手机继续使用全屏和安全区约束。
4. 生产 CSS 浏览器夹具检查主题、中英文、窄屏、触摸、禁用、焦点及更新页回归；执行 Rust 现有门禁。SSR 和浏览器夹具不等于原生 Dioxus 事件链路验收。

## 实现与验证

- 产品改动位于 app.css 和 settings.rs；未修改 SSH/SFTP、运维动作、终端绘制、状态管理或现有回调。已完成的更新逻辑保留。
- 共用中性表面、边框、主次/危险按钮、输入框、开关和可见焦点；移除工作区装饰阴影和固定蓝色选中渐变。修复主题根节点 token 依赖计算，浅色菜单和用户强调色不再继承固定深色/蓝色值。
- 设置标题与内容间距统一；所有分类支持窄窗口。安全弹窗指纹可换行，手机正文独立滚动、操作区可见；URL 输入同样使用 16px，普通手机表单和操作目标为 44px。
- Rust：最终 fmt、workspace all-targets check、默认及 all-features Clippy 均通过；`cargo test --workspace -- --test-threads=1` 为 512 项通过、1 项既有忽略。较早默认调度曾全通过；最终两次默认并发重跑均在 `kt-update::tests::checks_downloads_once_and_binds_asset_id` 遇到本地 HTTP 响应提前关闭（分别发生在查询和下载阶段），该项单独复测与完整串行测试通过。本次未修改此测试或更新业务实现，不能将默认并发测试记为稳定通过。
- v0.1.5 发布前已修复上述 HTTP 测试故障：macOS 接受的 socket 继承非阻塞 listener，原有读取会立即返回 WouldBlock 并被误判为空连接；accept 后显式恢复阻塞模式。修复后定向用例连续 10 次通过，串行及默认并发 workspace 测试均为 512 项通过、1 项既有忽略。
- CSS：PostCSS 与 CSS-tree 解析、游离声明及重复属性检查通过；git diff --check 通过。
- 浏览器：全局 1984 项检查和更新页 915 项回归通过。覆盖浅深色、中英文、320/360/390/640/760/1000/1440px 宽度、手机横屏、长名称/指纹、键盘 inset、禁用、原生 checkbox 状态、键盘焦点、子菜单和减少动态效果；自定义黑/白/黄/绿/红强调色按钮对比度检查通过。
- 全局预览和测试工具位于本会话 scratch；设置、连接、分组及认证界面由生产 Rust 组件生成 SSR，原生窗口拖动、系统发现和初始分类由测试适配器提供；终端/文件/运维/编辑器工作区使用生产 CSS 的布局夹具。浏览器数据不是生产 Dioxus 事件链路端到端结果。
