# 现代化更新界面

## 目标与依据

按已批准计划 `.pi/plan/现代化重构检查更新界面与完整状态交互-20261016-1015.md` 实施，范围是更新状态卡片、发布日志、进度、主题及重启确认交互和必要数据扩展。保留无关改动，不执行 Git 写操作或替换正式应用。

## 实施决策

- 复用 kt-update 服务与重启保护，展示组件与操作编排分离。
- 日志由同一次 Release 响应提供，使用 Markdown 事件转换为 Dioxus 节点；不注入 HTML、不加载图片，正文限制 64KiB 并明确提示。
- 真实下载进度与重启准备状态分开；辅助进程安装期间不虚构百分比。
- 更新弹层位于主界面 inert 之外并显式传递主题与强调色，模态框管理焦点、Esc 和恢复。
- 检查取消为独立中性终态，不更新成功检查时间、不增加失败计数。
