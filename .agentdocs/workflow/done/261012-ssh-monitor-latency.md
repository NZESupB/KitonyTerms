# SSH 会话延迟测量

## 目标与范围

仅修改监控延迟及测试，保持网络与连接配置不变。

## 决策

使用已连接 SSH 监控通道的轻量心跳 RTT，移除独立 TCP connect 探测，避免测得 TUN 本地握手时间及代理路径不一致。每轮标记带序号，拒绝旧心跳响应。超时仍使用 0 表示未知；真实短延迟仍允许 1ms。心跳计时不包含后续资源采样。

## 实施与验证

- [x] 删除 TCP 探测及会话参数，改用带序号心跳。
- [x] 增加进程内 SSH 延迟、超时恢复、旧响应、慢采样与连接数验证。
- [x] 定向测试及 workspace 门禁：monitor、roundtrip、fmt、check、test、Clippy（含 all-features）全部通过。
- [x] 最终差异复核：生产代码仅涉及 monitor.rs 和 session.rs，UI 与网络配置未修改。

回归测试覆盖 80ms、250ms 远端等待、心跳丢失与迟到标记、700ms 资源采样隔离、单 TCP 连接及断开后停止采样。断开验证遵循现有先断 SSH 再回收任务的流程，检查 Closed 事件与后续无采样，不要求远端收到单独 channel-close。

真实 TUN 环境尚未验收：需保持原配置，对同一目标收集至少 20 次采样，并与同路径轻量 SSH 请求往返计时比较。该测量包含 SSH 与远端调度开销，不等同于 ICMP RTT。
